# E：上传、填写、核对

只有当前岗位和网站已获填写/上传授权才进入。若只批准改简历，先交付 PDF 再询问用这份文件填写哪个明确页面；已有授权不重复确认。

## 准备

- 从状态取得当前岗位、入口和已核验 PDF 路径/指纹。重新读取页面确认公司/批次/岗位，不能默认使用其他聊天的当前页。
- 查清多志愿共用简历或逐岗上传。保留内推渠道，除非用户要求变更。
- 检查适用的项目规则与当前批准稿；有冲突时说明，不悄悄改正文。AI 工具使用描述由真实经历与岗位需求决定，不自动添加标签。
- 先清点宿主已连接的标签页，按公司、岗位、批次和账号准确复用，保留未提交输入；清点失败不代表目标不存在，不据此另开重复页。用已连接浏览器；登录/验证码请用户处理。工具拒绝时说明动作与原因，不换接口绕过。

## 填写

1. 有简历解析则先上传确认 PDF 并等解析完成，再修字段，避免解析覆盖后续修改。
2. 简历有的信息直接摘录该版本；缺失字段按需查本地配置指定的私有填表资料，仍缺少才集中提问。薪资/币种/薪数、到岗、调剂、志愿顺序不套用其他公司答案。
3. 建立字段→值→来源→读回结果映射。状态只记来源引用与完成情况，不复制完整隐私信息。
4. 每个项目独立核对标题、职责、描述、日期。修正解析串入的题目/日期/其他项目文字，检查长字段截断；无明确要求不填项目来源。
5. 页面要求精确结束日时：已结束项目按真实结束日期；仍在进行的项目按用户时区取执行日期；项目状态或时区影响结果但未知时询问，不套用其他人的日期。
6. 不盲目覆盖用户手填字段；已授权核对纠错时可据确认材料修正明显错误并汇报，新选择性信息先问。
7. 核对附件文件名、时间/大小、预览或可下载内容。同名不足以证明当前版本，无法核实则标附件待核实。

## 结束与恢复

- 读回必填项、各项目和附件；报告公司/岗位、附件版本、校验错误、未完成字段、是否保存，以及“未提交，请审核”。
- 只有清楚独立于提交的保存草稿控件才可使用。无持久化证据标 unknown/unsaved，不宣称已保存；无保存按钮则提醒刷新/关闭可能丢失。
- 崩溃/重启/重登后先查页面与附件，按已有授权恢复缺失内容，不反复问同一授权；实际工具权限仍遵循。
- 默认不点击提交、不撤销、不发消息。用户明确改变边界时核对当时项目规则与具体授权，不靠旧状态推断。
- ready_for_user_submit 与 submitted_observed 分开；只有用户反馈或成功页才记后者，并记录证据。
