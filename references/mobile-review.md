# 手机审阅与反馈

## 触发与能力选择

用户说“正在用手机”“手机能看”时，在当前申请状态记录 `mobile_review: true`，沿用直到用户改变要求。根据当前环境选择交付，不假设朋友拥有作者的插件或账号功能：

1. 宿主支持对话内可编辑 HTML 时，直接呈现完整简历与 JD 关键词视图。可使用已安装的 visualize 或等价能力，遵循该工具接口。
2. 已授权使用 Sites 或等价云服务时，可附同版在线审阅链接，复用现有页面并保留访问范围。手机审阅请求本身不授权将个人简历公开上网；若服务无法提供所需访问控制，先交付本地版本。
3. 缺少上述能力时，交付自包含、可下载的可编辑 HTML；聊天内提供逐条建议供反馈。说明下载/浏览器打开方式与宿主限制，不把链接、截图或代码块说成已内嵌渲染。

用户明确要求两种视图时，完成可用部分并说明缺项；不要安装未经授权的桥接器，也不伪造链接。短问答无需每轮重复整份材料。

## 内容与交互

- 完整简历适配手机宽度，原文只读，对照与高亮可切换。当前建议正文可编辑，稳定条目 ID 和审阅版本保留。
- 提供明确的保存或导出操作。宿主支持向聊天发送修改时，须由用户显式点击，载荷包含岗位、版本、条目 ID 和实际文本；无宿主接口时用导出文件或复制修改文本反馈，不制作无效发送按钮。
- 浏览器编辑、保存下载、云端更新和助手修改正式文件是不同状态。先读回用户编辑，不用旧生成脚本覆盖；不声称实现了未实现的同步。
- JD 呈现完整职责与要求、岗位名/代码、来源链接与核实日期；关键词在原句中高亮，保留“至少一种”“优先”等限定。仅有摘要或历史快照时标明范围。

## 验收

多种视图必须共享正文与版本。实际检查手机宽度、横向溢出、原文/高亮切换，以及编辑保存后重开是否保留。工具不可用时如实标明未验收项。区分本地交互检查与真实宿主发送，不为测试发送用户消息。路径、地址、版本和实际可用交付方式写入现有申请状态。
